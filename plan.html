Display Modes Implementation Plan

For agentic workers: REQUIRED SUB-SKILL: use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task by task. Steps use checkboxes.

Goal: Two pinnable one-click shortcuts that switch Windows between Compact (taskbar auto-hide on, 175% scale) and Roomy (auto-hide off, 225% scale).

Architecture: One helper module with two functions (taskbar auto-hide, display scale), two thin mode scripts that call it and verify the result, and an installer that creates the .lnk shortcuts. Everything is PowerShell with inline C# P/Invoke.

Tech Stack: PowerShell 5.1+ (powershell.exe), inline C#, git, gh CLI.

Spec: P:\Proton Drive\My files\Projects\display-modes\design.html

Global Constraints

  • Windows 11, one 4K primary display; no admin rights, no downloads, no third-party binaries.
  • Compact = auto-hide on + 175%. Roomy = auto-hide off + 225%.
  • Changes apply instantly: no sign-out, no Explorer restart.
  • Shortcuts run powershell.exe -NoProfile -WindowStyle Hidden -File ... and are pinnable.
  • Silent on success; a message box on any mismatch. Scripts are idempotent.
  • Scale uses the undocumented DisplayConfigSetDeviceInfo (type -4; get is type -3). Taskbar uses documented SHAppBarMessage.
  • Docs and plans are HTML; README.md is the one exception and must exist and stay current.
  • GitHub repo is private.

Review Focus

  • Project path contains spaces (Proton Drive\My files): shortcuts and scripts must still run.
  • Mode already active: nothing changes, no flicker, no message.
  • Requested scale is not offered by the display (list differs per monitor): report it, don't set a wrong value.
  • Taskbar window not found (Explorer restarting): report it, don't claim success.
  • Run from a hidden shortcut: the failure message box must still appear in front.

File Structure

  • DisplayModes.ps1: helper functions only, no side effects when dot-sourced.
  • Compact.ps1, Roomy.ps1: apply one mode each.
  • Install-Shortcuts.ps1: creates Compact.lnk, Roomy.lnk and icons.
  • tests/Test-DisplayModes.ps1: plain assertion script; saves the current state and restores it at the end.
  • README.md, .gitignore.

  • Write the test Test-TaskbarRoundTrip: record the original state, call Set-TaskbarAutoHide -Enabled $true and assert it returns $true and Get-TaskbarAutoHide is $true; repeat for $false; restore the original.

Task 3: Display scale

Files: Modify DisplayModes.ps1, tests/Test-DisplayModes.ps1.

Interfaces: Produces Get-DisplayScale : [int] (percent, e.g. 225) and Set-DisplayScale -Percent [int] : [int] (returns percent read back). Throws a message naming the supported percentages if the requested one is not offered. Targets the primary display only.

  • Write tests: Test-ScaleCurrent asserts Get-DisplayScale equals round(AppliedDPI / 96 * 100) from HKCU:\Control Panel\Desktop\WindowMetrics (currently 216 = 225); Test-ScaleRoundTrip sets 175, asserts the return is 175, sets 225, asserts 225, then restores the original; Test-ScaleUnsupported asserts Set-DisplayScale -Percent 137 throws and leaves the scale unchanged.
  • Run the test script. Expected: FAIL, functions not defined.
  • Implement in DisplayModes.ps1. Find the primary source's adapter id and source id with GetDisplayConfigBufferSizes and QueryDisplayConfig. Call DisplayConfigGetDeviceInfo type -3 to get minScaleRel, curScaleRel, maxScaleRel (steps relative to the recommended scale). Map steps to the fixed list 100, 125, 150, 175, 200, 225, 250, 300, 350, 400, 450, 500 anchored on the recommended step, which is -minScaleRel places from the list start. Set via DisplayConfigSetDeviceInfo type -4.
  • Re-run the test. Expected: PASS, and the screen re-scales instantly. If the call does nothing on this build, report it to the user rather than working around it.
  • Commit feat: display scale helper.

Task 4: Mode scripts

On any mismatch or exception it shows a topmost System.Windows.Forms.MessageBox naming what did not apply, then returns $false. Each mode script dot-sources the helper via $PSScriptRoot and calls Set-DisplayMode with its values.

  • Write tests: Test-ModeApplies calls Set-DisplayMode -AutoHide $true -Percent 175, asserts $true and both getters agree; same for $false/225. Test-ModeIdempotent calls the same mode twice and asserts the second call returns $true without invoking either setter (check by mocking the setters with counters). Replace the message-box call with an overridable $script:ShowError scriptblock so a test can assert it fires on a failed read-back.

  • Implement Set-DisplayMode: read current state, only call a setter whose value differs, read back, compare.
  • Create Compact.ps1 (-AutoHide $true -Percent 175) and Roomy.ps1 (-AutoHide $false -Percent 225).
  • Run the tests, then run each script directly with powershell -NoProfile -File Compact.ps1. Expected: PASS, and the display ends in the right state with no output.
